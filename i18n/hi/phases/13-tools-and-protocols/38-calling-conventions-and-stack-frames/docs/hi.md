# कॉलिंग कन्वेंशन और स्टैक फ्रेमः सिस्टम वी, विंडोज x64, और AArch64

> एक डिमॉन्डेशन दिखाता है कि कौन सा रजिस्टर एक फ़ंक्शन पढ़ता है। केवल एबीआई बताता है कि उन रजिस्टरों का क्या अर्थ है, और एबीआई ऑब्जेक्ट हेडर द्वारा चुना जाता है, इसलिए यह सबक पहले हेडर पढ़ता है और फिर प्रत्येक रजिस्टर को उस नियम के खिलाफ जांचता है जो इसे वहां रखता है।

**Type:** Build
**Languages:** Python, C, x86-64 and AArch64 assembly
**Prerequisites:** Phase 13 · 32 (ELF from scratch), Phase 13 · 33 (disassembly and control flow)
**Time:** ~140 minutes

## सीखने के लक्ष्य

- ऑब्जेक्ट हेडर से कॉल कन्वेंशन चुनेंः ELF x86-64 System V psABI है, COFF AMD64 Microsoft x64, ELF AArch64 AAPCS64, Mach-O arm64 Apple का संस्करण है।
- प्रत्येक एबीआई के लिए एक फ़ंक्शन के बाइट द्वारा बाइट के प्रोग्रू को डिकोड करें और प्रत्येक सहेजे गए रजिस्टर, रिटर्न एड्रेस और फ्रेम पॉइंटर को एंट्री स्टैक पॉइंटर से इसके ऑफसेट पर रखें।
- फ़ंक्शन के पैरामीटर रजिस्टर को उन रजिस्टरों से इनपुट करें जो यह उन्हें लिखने से पहले पढ़ता है, और स्टैक तर्क स्लॉट को एंट्री स्टैक पॉइंटर के ऊपर लोड से।
- माइक्रोसॉफ्ट x64 के स्थिति स्लॉट से सिस्टम V के स्वतंत्र रजिस्टर अनुक्रमों को बताएं, और दोनों AAPCS64 के NGRN और NSRN काउंटर से।
- स्रोत हस्ताक्षर, विनिर्देश में नियम और संकलक के अपने ही विघटन डेटा के साथ प्रत्येक निष्कर्ष की जाँच करें `.pdata`,`.xdata`और `.eh_frame`. .
- तुलना करें कि गिद्रा, आईडीए, बाइनरी निंजा, रडारे2, रिजिन और एएनजीआर का नाम कैसे रखा जाता है और एक ही तथ्य को पुनर्प्राप्त करते हैं, और रिकॉर्ड करते हैं कि उनका आउटपुट स्रोत से कब असहमत है।

## समस्या

आप संकलित किया `convention.c`के लिए लिनक्स x86-64 पर `-O2`और रडार2 6.2.4 से उनके तर्क के लिए पूछा।`eight_args`उसने सात से उत्तर दिया:`rdi`,`rsi`,`rdx`,`r8`,`r9`,`rsp+0x8`और `rsp+0x10`. सी स्रोत में आठ मापदंड हैं. बाइट्स पढ़ते हैं`%rcx`ठीक एक बार, में `leaq (%rdx,%rcx), %rax`, और उपकरण के चर वसूली एक रजिस्टर नहीं गिना जो केवल एक पते के अंदर दिखाई देता है.

फिर आपने रिज़िन 0.9.1 में उसी फ़ाइल का विंडोज बिल्ड खोला। यह सम्मेलन को बताया कि`amd64`और पाया `r8`,`rcx`,`rdx`वस्तु COFF है, तो सम्मेलन माइक्रोसॉफ्ट x64 है, चौथा रजिस्टर तर्क है `r9`दोनों उपकरण एक ही स्रोत में अलग रजिस्टरों को याद करते हैं।

सूची निर्देशों का एक अनुक्रम है। एक कॉल कन्वेंशन एक अनुबंध है जो सूचीबद्ध करने के बाहर रहता हैः कौन से रजिस्टर तर्क ले जाते हैं, जिन्हें कॉल करने वाले को संरक्षित करना चाहिए, जहां वापसी पता और स्टैक तर्क बैठते हैं, और कॉल करने वाले को स्टैक पॉइंटर के ऊपर क्या छोड़ना चाहिए। चार दस्तावेजों में इस मामले में महत्वपूर्ण अनुबंधों की परिभाषा है। सिस्टम V AMD64 psABI (वर्जन 1.0, 12 मार्च 2025 की बिल्ड) धारा 3.2.1 से 3.2.3 तक। माइक्रोसॉफ्ट x64 कॉल कन्वेंशन, स्टैक उपयोग, और प्रलोग और एपिलॉग पृष्ठ (पृष्ठ दिनांक 2018-12-17 से 2025-03-19 तक) । आर्म एएपीसीएस 64 रिलीज 2025Q4 (23 जनवरी 2026) धारा 6.1 से 6.9 तक। एप्पल के arm64 प्लेटफॉर्म नोट्स। यह पाठ उन नियमों को पढ़ता है, उन्हें एक सी फ़ाइल पर लागू करता है जो तीन तरीकों से संकलित है, और विश्लेषक का निर्माण करता है जो सूची को पैरामीटर स्थानों, सहेजे गए रजिस्टरों और फ्रेम ऑफसेट की एक चेक की गई सूची में बदल देता है।

## एक शीर्षक नियम पुस्तिका चुनता है

`convention.c`बारह कार्य करते हैंः `leaf_add`,`eight_args`,`mixed`,`by_value`,`big_ret`,`sum_varargs`,`keeps`, और पांच कॉलर्स `extern`संरचनाओं का उपयोग `long long`, क्योंकि `long`यह 4 बाइट्स MSVC लक्ष्य पर और 8 बाइट्स अन्य पर है, और एक संरचना है कि आकार परिवर्तन कन्वेंशन बदलता है। एप्पल क्लांग 17.0.0 इस मशीन से इसे सात बार संकलित कियाः`-target x86_64-unknown-linux-gnu`,`x86_64-pc-windows-msvc`और `aarch64-unknown-linux-gnu`पर`-O0`और `-O2`और `arm64-apple-macos`पर`-O2`. कोई लिनक्स या विंडोज हेडर स्थापित नहीं हैं, इसलिए फ़ाइल यह घोषणा करता है कि यह क्या जरूरत है और केवल क्लिंग के अपने शामिल है `stdarg.h`और `stddef.h`. .

`describe_object()`में `code/main.py`4 बाइट जादू संख्या और एक मशीन क्षेत्र पढ़ता है और अनुबंध का नाम देता हैः

| Header | Field | Value | Rulebook |
|---|---|---|---|
| `7f 45 4c 46` ELF | `e_machine` at offset 0x12 | 62 | System V AMD64 psABI |
| `64 86` COFF | `Machine` at offset 0 | 0x8664 | Microsoft x64 |
| `7f 45 4c 46` ELF | `e_machine` | 183 | AAPCS64 |
| `cf fa ed fe` Mach-O 64 | `cputype` at offset 4 | 0x0100000c | AAPCS64 with Apple differences |

तीनों अनुबंध तालिका की लगभग हर पंक्ति पर असहमत हैं। प्रत्येक मूल्य को हेडर पंक्ति में नामित दस्तावेज़ से उद्धृत किया गया है, और प्रत्येक को फिक्स्चर के साथ परीक्षण द्वारा जांच किया जाता है।

| Rule | System V psABI | Microsoft x64 | AAPCS64 |
|---|---|---|---|
| Integer arguments | `%rdi %rsi %rdx %rcx %r8 %r9`, next free register | `RCX RDX R8 R9`, by position | `x0` to `x7`, by NGRN |
| Floating-point arguments | `%xmm0` to `%xmm7`, next free register | `XMM0` to `XMM3`, by position | `v0` to `v7`, by NSRN |
| Integer result | `%rax`, then `%rdx` | `RAX` | `x0`, then `x1` |
| Floating-point result | `%xmm0`, then `%xmm1` | `XMM0` | `v0` |
| Result too large for registers | address passed in `%rdi` "as if it were the first argument", returned in `%rax` | pointer in `RCX`, arguments shifted right, returned in `RAX` | address in `x8`, `x0` to `x7` untouched |
| Callee-saved | `%rbp %rbx %r12` to `%r15` | `RBX RBP RDI RSI RSP R12` to `R15`, `XMM6` to `XMM15` | `r19` to `r29`, `SP`, low 64 bits of `v8` to `v15` |
| First stack argument on entry | `8(%rsp)` | `40(%rsp)`, above a 32-byte shadow store | `0(sp)` |
| Below the stack pointer | 128-byte red zone | "considered volatile" | no red zone (Apple: 128 bytes) |
| Alignment at the call | `(%rsp + 8)` multiple of 16 on entry | 16-byte aligned outside prolog and epilog | `SP mod 16 = 0` |
| Variadic marker | `%al` holds an upper bound on vector registers used | floats duplicated in the integer register | none in registers; Apple uses 8-byte stack slots |

## प्रणाली V: दो स्वतंत्र रजिस्टर अनुक्रम और एक लाल क्षेत्र

psABI 3.2.3 प्रत्येक तर्क के प्रत्येक आठ बाइट को INTEGER, SSE, या MEMORY के रूप में वर्गीकृत करता है और फिर दो परस्पर नहीं होने वाली सूचियों से रजिस्टर को असाइन करता है। "INTEGER" "%rdi, %rsi, %rdx, %rcx, %r8 और %r9 अनुक्रम का अगला उपलब्ध रजिस्टर" लेता है। SSE लेता है `%xmm0``%xmm7`. "यदि किसी भी तर्क के आठ बाइट के लिए कोई रजिस्टर उपलब्ध नहीं है, तो पूरे तर्क को स्टैक पर पारित किया जाता है", और स्मृति तर्क "स्टैक पर उल्टे (दाएं से बाएं) क्रम में धकेल दिए जाते हैं।

`eight_args(a, b, c, d, e, f, g, h)`पर`-O2`27 बाइट्स है:

```text
      10: 48 01 fe                     	addq	%rdi, %rsi
      13: 48 8d 04 0a                  	leaq	(%rdx,%rcx), %rax
      17: 48 01 f0                     	addq	%rsi, %rax
      1a: 4c 01 c0                     	addq	%r8, %rax
      1d: 4c 01 c8                     	addq	%r9, %rax
      20: 48 03 44 24 08               	addq	0x8(%rsp), %rax
      25: 48 03 44 24 10               	addq	0x10(%rsp), %rax
      2a: c3                           	retq
```

छह रजिस्टर, फिर दो लोड पर `8(%rsp)`और `16(%rsp)`. psABI के चित्र 3.3 में "मेमोरी तर्क आठबाइट 0" को `16(%rbp)`कब`%rbp`फ्रेम आधार है, जो है `8(%rsp)`किसी भी धक्का से पहले प्रवेश पर। `g`8 पर है।`h`16 साल की उम्र में।

`mixed(int i, double d, long long l, float f)`इन दोनों सूचियों को दिखाता है।`%edi`और `%rsi`, पहला और दूसरा INTEGER रजिस्टर।`%xmm0`और `%xmm1`, SSE रजिस्टर की पहली और दूसरी.`cvtsi2sd %edi, %xmm2`और `%xmm2`एक स्क्रैच रजिस्टर है कि फ़ंक्शन पढ़ने से पहले लिखता है। एक विश्लेषक जो `cvtsi2sd`एक रीड एक तीसरे फ्लोटिंग-पॉइंट तर्क का आविष्कार करता है। रडार2 ने ठीक यही किया और रिपोर्ट की।`mixed`जैसे `(double arg1, double arg2, double arg3)`में `xmm0`,`xmm1`,`xmm2`. .

`by_value(struct pair p)`एक 16-बाइट संरचना को दो INTEGER आठबाइट्स में पारित करता है `%rdi`और `%rsi`, और उसी तरह लौटाता हैः `leaq 0x1(%rdi), %rax; leaq -0x1(%rsi), %rdx; retq`. .`big_ret(long long seed)`32 बाइट्स लौटाता है, जो वर्ग स्मृति है, और psABI कहते हैं "कॉलर रिटर्न मूल्य के लिए स्थान प्रदान करता है और इस भंडारण का पता %rdi में पारित करता है जैसे कि यह पहला तर्क था। "`seed``%rsi`, और फ़ंक्शन  से शुरू होता है`movq %rdi, %rax`क्योंकि "%rax पर वापस करने पर उस पते को शामिल किया जाएगा जिसे %rdi में कॉल करने वाले द्वारा भेजा गया है। "

लाल क्षेत्र अन्य प्रणाली V हस्ताक्षर है। psABI 3.2.2: "%rsp द्वारा इंगित स्थान से परे 128-बाइट क्षेत्र को आरक्षित माना जाता है और संकेत या बाधित हैंडलर द्वारा संशोधित नहीं किया जा सकता है।"`-O0`,`eight_args`है `pushq %rbp; movq %rsp, %rbp`और फिर छह दुकानों के लिए `-0x8(%rbp)`पार`-0x30(%rbp)`बिना किसी`subq`दुकानें स्टैक पॉइंटर से 48 बाइट नीचे हैं।`-O2`निर्माण`sum_varargs` के साथ 88 बाइट्स आवंटित करता है`subq $0x58, %rsp`और फिर रजिस्टर सहेजें क्षेत्र लिखता है `-0x58(%rsp)``-0x80(%rsp)`: 128 बाइट्स स्टैक पॉइंटर से नीचे, पूरे लाल क्षेत्र. के साथ एक ही फ़ाइल का निर्माण `-mno-red-zone`और `leaf_add`लाभ `pushq %rax`और एक `addq $0x8, %rsp`अपने 8 बाइट्स स्थानीय लोगों को स्टैक पॉइंटर के ऊपर रखने के लिए।

वेरिएडिक कॉल एक रजिस्टर जोड़ते हैं। "%al का उपयोग 0 से 8 तक ऊपरी सीमा के साथ वैक्टर रजिस्टरों की संख्या निर्दिष्ट करने के लिए छिपे हुए तर्क के रूप में किया जाता है। `call_varargs`यह सेट करता है के साथ `xorl %eax, %eax`पर`-O2`और `movb $0x0, %al`पर`-O0`. .`sum_varargs`पहले पढ़ता हैः `testb %al, %al; je`आठ पर कूद `movaps %xmmN`जब कोई वेक्टर रजिस्टर इस्तेमाल नहीं किया गया था तब सहेजता है।

## माइक्रोसॉफ्ट x64: पोजीशन, एक छाया स्टोर, और कोई रेड जोन नहीं

1. `describe_object()`ELF, COFF या Mach-O हेडर और प्रतीक तालिका को पढ़ता है और ABI और फ़ंक्शन सूची लौटाता है।

3. `effect_x86()`और `effect_arm()`एक निर्देश को रीड्स, एड्रेस रीड्स, राइट्स, लोड, स्टोर और स्टैक पॉइंटर डेल्टा में बदल दें। अंतिम एटी एंड टी ऑपरेंड गंतव्य है; पहला एआरएच 64 ऑपरेंड स्टोर, तुलना और शाखाओं को छोड़कर गंतव्य है। `lea`पता पढ़ता है और कुछ भी लोड नहीं करता है।`mov`,`cvtsi2sd`,`setcc`, और शून्य शब्द`xor r, r`एक कॉल पूरे अस्थिर सेट लिखता है। एक पूर्व-अनुक्रमित स्टोर चलता है।`sp`पहुँच और पोस्ट-अनुक्रमित लोड के बाद इसे स्थानांतरित करने से पहले।
4. `analyze_function()`शरीर को एक बार ऊपर ले जाता है।`ret`यह स्टैक पॉइंटर की गहराई को उसके प्रवेश मूल्य से नीचे ट्रैक करता है, इसलिए एक मेमोरी ऑपरेंड`disp(%rsp)`प्रवेश के समय में है `disp - depth`और `disp(%rbp)`है `frame_pointer + disp`. यह तर्क-वर्ग रजिस्टरों को रिकॉर्ड करता है जो उन्हें लिखने से पहले पढ़े जाते हैं, एबीआई के पहले स्टैक तर्क ऑफसेट पर या उससे ऊपर लोड करता है, फ़्रेम में तर्क रजिस्टरों को स्टोर करता है, वर्तमान स्टैक पॉइंटर से नीचे पहुंचता है, और प्रत्येक कॉल पर गहराई।
5. `_return_registers()`एक परिणाम रजिस्टर जब उसके अंतिम पहुँच से पहले बाहर निकलने एक लेखन है रखता है. एक डेटा ऑपरेंड के रूप में पढ़ा उम्मीदवार को मारता है; एक पते के आधार के रूप में पढ़ा नहीं करता है, जो है जो रखता है `rax`जीवित में `big_ret`माइक्रोसॉफ्ट x64 के अंतर्गत, जहां `movq %rcx, %rax`इसके बाद दुकानों से `(%rax)`. .
6. `expected_locations()`एक सी हस्ताक्षर पर तीन नियम पुस्तकों को लागू करता हैः दो सिस्टम वी सूची आठ बाइट वर्गों के साथ, माइक्रोसॉफ्ट स्थिति स्लॉट उप-संदर्भ स्ट्रक्चर के साथ, और AAPCS64 counters के साथ `x8`16 बाइट से ऊपर के परिणामों के लिए।
7. `run_checks()`दोनों की तुलना करता है और फ्रेम नियम जोड़ता हैः कॉल से सहेजे गए रजिस्टरों को सहेजा जाना चाहिए, `(rsp + 8) % 16 == 0`या `sp % 16 == 0`प्रत्येक कॉल पर, 32 बाइट्स छाया प्रत्येक माइक्रोसॉफ्ट कॉल पर, माइक्रोसॉफ्ट और AAPCS64 के तहत स्टैक पॉइंटर के नीचे कोई पहुंच नहीं और अधिकतम 128 बाइट्स सिस्टम V के तहत, और एक एपिलोग जो स्टैक पॉइंटर के साथ प्रोग्यू को उसके प्रवेश मूल्य पर दर्शाता है।
8. `seh_cross_check()`और `eh_frame_cross_check()`बिना निर्मित वस्तुओं के विघटन डेटा पढ़ें `-fno-asynchronous-unwind-tables`और इसे प्रोग्रैग विश्लेषण के साथ तुलना करें।

तीन और आदेश मौजूद हैं।`python3 code/main.py analyze convention-x86_64-windows-O2 keeps`एक फ़ंक्शन प्रिंट करता है। `python3 code/main.py object FILE`शीर्षक के फैसले को प्रिंट करता है।`python3 code/main.py seh`डिकोड को प्रिंट करता है `UNWIND_INFO`प्रत्येक कार्य का जो एक है।

इस सबक में शामिल है `outputs/skill-calling-conventions-and-stack-frames.md`. इसका उपयोग आप बनाया गया एक वस्तु, इसकी सूची और सी हस्ताक्षर पैरामीटर स्थानों, एक फ्रेम लेआउट, एक वापसी रजिस्टर में बदलने के लिए, और यह नियम के खिलाफ हर निष्कर्ष की जांच करने के लिए किया जाता है पर आधारित है और संकलक के विन्ड डेटा के खिलाफ. यह शीर्षकों के ABI निर्णय की आवश्यकता है पहले, पढ़ने के लिए मना करता है ।`cvtsi2sd`या `xor r, r`गंतव्य के रूप में पढ़ता है, और पहले असहमति के साथ समाप्त होता है।

सत्यापन से साबित होना चाहिएः

- सात वस्तुओं के नाम प्रणाली वी, माइक्रोसॉफ्ट x64, AAPCS64 और एप्पल arm64 के ELF, COFF और Mach-O हेडर
- प्रत्येक वस्तु के प्रतीक तालिका Mach-O के साथ एक ही बारह कार्यों को सूचीबद्ध करता है`_`उपसर्ग और `ltmp0`लेबल हल
- सूची पार्सर रखता है `ext`कॉल लक्ष्य के रूप में और AArch64 तत्काल रखता है जैसे `#-0x30`अछूता
- `leaq (%rdx,%rcx), %rax`दो पते रजिस्टर पढ़ता है और कुछ भी लोड नहीं करता है; `xorl %eax, %eax`और `cvtsi2sd`केवल लेखन-केवल हैं; पूर्व-अनुक्रमित हैं `stp`चाल `sp`दुकान से पहले और पोस्ट-इंडेक्स`ldp`लोड के बाद
- `keeps`पर`-O2`है `55 41 56 53`सिस्टम V पर 24 बाइट फ्रेम और कोई फ्रेम पॉइंटर नहीं, `56 57 53 48 83 ec 20`माइक्रोसॉफ्ट x64 पर 56 बाइट फ्रेम के साथ, और `a9bd7bfd`-48 पर रिकॉर्ड के साथ AArch64 पर पहला
- एप्पल बिल्ड रिकॉर्ड को -16 पर रखती है चार सहेजे गए रजिस्टर से ऊपर
- प्रत्येक फ़ंक्शन में एक फ्रेम पॉइंटर है `-O0`लिनक्स पर और कोई नहीं `-O2`और `-fno-omit-frame-pointer`एक संरेखण धक्का के साथ इसे वापस लाता है
- `-O0`पत्ती प्रणाली V के तहत लाल क्षेत्र के 8 बाइट्स का उपयोग करता है, `pushq %rax`Microsoft x64 के अंतर्गत, तथा `sub sp, sp, #0x10`AAPCS64 के अंतर्गत; `-mno-red-zone`लाल क्षेत्र का उपयोग हटा देता है
- प्रत्येक एपिलॉग अपने प्रोग्रू को दर्शाता है और स्टैक पॉइंटर प्रवेश पर वापस है
- `eight_args`6 रजिस्टर और स्लॉट 8 और 16, 4 रजिस्टर और स्लॉट 40 से 64 तक पढ़ता है, या `x0``x7`, दोनों अनुकूलन स्तरों पर
- `mixed`है `rdi, xmm0, rsi, xmm1`प्रणाली V और `rcx, xmm1, r8, xmm3`Microsoft x64 के तहत, के साथ `xmm0`दोनों पर परिणाम
- 16-बाइट संरचना प्रणाली V और AAPCS64 के तहत दो रजिस्टरों में और संदर्भ के तहत माइक्रोसॉफ्ट x64 के तहत एक छिपे हुए पॉइंटर के पीछे यात्रा करता है
- 32 बाइट संरचना के माध्यम से वापस आता है `rdi`,`rcx`या `x8`
- विविधतापूर्ण कैली पढ़ता है `%al`, घरों `rdx, r8, r9`16, 24, 32, बचत करता है `x1``x7`और `q0``q7`, या Apple पर कॉल करने वाले के स्टैक पॉइंटर पढ़ता है
- कॉल करने वाले अपेक्षित रजिस्टर सेट करते हैं, 0 और 8 पर 7 और 8 या 5 से 8 पर 32 से 56, शून्य पर स्टोर करते हैं `%al`वेरिएडिक कॉल के लिए, और परिणाम बफर पते में पारित `rdi`,`rcx`या `x8`
- सभी 489 जांच अपने नियमों के साथ सहमत हैं
- छठी `UNWIND_INFO`प्रविष्टियाँ प्रलाप विश्लेषण से मेल खाती हैं और पत्तियों में कोई नहीं है
- 24 एफडीई सहेजे गए रजिस्टर ऑफसेट और सबसे गहरे स्टैक पॉइंटर से मेल खाते हैं
- उपकरण रिकॉर्ड रडार2 की कैप्चर करता है `amd64`और `ms`, रिजिन की `amd64`COFF वस्तु पर, गायब `rcx`, तीन डबल्स, और Angr के प्रोटोटाइप
- साइट मॉड्यूल में एम्बेडेड आंकड़ा डेटा विश्लेषक के आउटपुट के बराबर है

## उत्पादन विफलता मोड

| Failure | What the weak tool reports | What the analysis must prove |
|---|---|---|
| COFF object read as System V | `rdi` and `rsi` as arguments that the function never reads | The header says 0x8664; the convention is Microsoft x64 |
| Register read only inside a `lea` | Seven arguments for an eight-argument function | Base and index registers are reads |
| `cvtsi2sd` destination counted as a read | A third double argument in `xmm2` | The first write to `xmm2` is a write; `mixed` has two SSE arguments |
| Positional slots read as sequences | `xmm0` named as the double argument on Windows | Slot 1 is `XMM1`, slot 3 is `XMM3` |
| `push rbp` taken as a frame pointer | A frame pointer in an `-O2` function that uses `rbp` as an accumulator | Only `mov %rsp, %rbp` after the push creates one |
| Red zone measured from the entry stack pointer | 216 bytes "below the stack pointer" | 128 bytes below the current stack pointer after an 88-byte `sub` |
| Shadow store treated as locals | Stack arguments at 8 to 32 | Microsoft stack arguments start at 40 |
| `lea` treated as a load | A stack argument at `0x60(%rsp)` in a variadic callee | `lea` computes `overflow_arg_area`; it loads nothing |
| Hidden pointer read as a normal argument | `big_ret(void *, long long)` | The pointer is stored through and copied to `rax`, `rax`, or stays in `x8` |
| Deepest CFA compared with the prologue frame | A mismatch on a caller that pushes outgoing arguments | Compare with the deepest stack pointer the body reaches |
| Convention asserted from the ISA | `amd64` for a COFF object | The format picks the rulebook, then the ISA picks the registers |
| Prototype trusted from one tool | Three doubles, or sixteen variadic parameters | The source signature or a second derivation must agree |
